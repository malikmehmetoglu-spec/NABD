# نبض 2.0 — إدارة العيادات

إعادة بناء كاملة لقسم العيادات. الصيدلية والمختبر خارج هذه النسخة وتُضاف لاحقاً كوحدات مستقلة.

## ما الذي تغيّر عن النسخة القديمة

| المشكلة في النسخة القديمة | الحل في 2.0 |
|---|---|
| كوكي `nabd-session=1` يتجاوز الحماية | الجلسة من Supabase Auth ويُتحقق منها عند الخادم في كل طلب (`src/proxy.ts`) |
| 57 مساراً بمفتاح الخدمة السري، بعضها بلا تحقق | لا يوجد مفتاح خدمة في التطبيق إطلاقاً، وكل وصول يمر عبر سياسات RLS |
| بيانات العيادات غير معزولة بضمان | RLS على كل جدول، مع 16 اختباراً تثبت العزل (`npm run test:db`) |
| حجز موعدين للطبيب في نفس الوقت | قيد في قاعدة البيانات يرفض التداخل |
| حفظ الزيارة والوصفة والدفعة بخطوات منفصلة | دالة `save_visit` تحفظ كل شيء في عملية واحدة، فإما ينجح كله أو لا يُحفظ شيء |
| السكرتارية ترى وتعدّل كل شيء | أدوار: مالك، طبيب، سكرتارية. السجل الطبي يكتبه الأطباء فقط |
| أيام المواعيد تُحسب بتوقيت الخادم | كل التواريخ بتوقيت العيادة (قابل للتغيير من الإعدادات) |
| أكثر من 5300 تنسيق مكتوب يدوياً | نظام تصميم واحد في `globals.css` ومكونات في `src/components/ui.tsx` |
| صفحات من 2500 إلى 4000 سطر | أكبر صفحة نحو 220 سطراً |
| أخطاء البناء مُتجاهَلة | TypeScript صارم وESLint يعملان في كل بناء |
| الاشتراك وحدود الخطة تُفحص في المتصفح فقط | الحالة والانتهاء والحدود مفروضة في قاعدة البيانات، ولا يعدّلها إلا أدمن المنصة |
| كلمات سر العيادات مخزّنة نصاً ويراها الأدمن | الأدمن لا يرى كلمات السر إطلاقاً؛ تسجيل الدخول عبر Supabase Auth فقط |
| بلا migrations ولا اختبارات | 6 migrations، و31 اختبار قاعدة بيانات، و12 اختبار وحدة |

## التشغيل لأول مرة

### 1. مشروع Supabase جديد
أنشئ مشروعاً جديداً على [supabase.com](https://supabase.com). لا تستخدم مشروع النسخة القديمة لأن الجداول مختلفة.

### 2. إنشاء قاعدة البيانات
الطريقة الأسهل: افتح **SQL Editor** في لوحة Supabase، وشغّل ملفات `supabase/migrations/` بالترتيب:
1. `20261112000001_core_schema.sql`
2. `20261112000002_security.sql`
3. `20261112000003_save_visit.sql`
4. `20261112000004_invites.sql`
5. `20261117000005_tighten_policies.sql`
6. `20261117000006_subscriptions_admin.sql`

أو عبر سطر الأوامر: `npx supabase link` ثم `npx supabase db push`.

### 3. إعدادات تسجيل الدخول
في **Authentication › Providers › Email**: إذا فعّلت "Confirm email" سيصل للمستخدم رابط تأكيد قبل أول دخول. في **URL Configuration** ضع رابط موقعك في Site URL.

### 4. متغيرات البيئة
انسخ `.env.example` إلى `.env.local` واملأ القيم من **Project Settings › API**:
```
NEXT_PUBLIC_SUPABASE_URL=...
NEXT_PUBLIC_SUPABASE_PUBLISHABLE_KEY=...
```
وضع القيم نفسها في Vercel ضمن **Settings › Environment Variables**.

### 5. التشغيل
```bash
npm install
npm run dev
```

### 6. حساب أدمن المنصة
سجّل حساباً عادياً من صفحة التسجيل **ولا تنشئ عيادة**. ثم في SQL Editor:
```sql
insert into platform_admins (user_id)
select id from auth.users where email = 'admin@example.com';
```
عند دخولك بهذا الحساب تُفتح لوحة الإدارة على `/admin`. غير الأدمن يرى صفحة غير موجودة.

## الاشتراكات

كل عيادة جديدة تبدأ بخطة **تجريبية لمدة 14 يوماً**. القواعد مفروضة في قاعدة البيانات، فلا يمكن تجاوزها من المتصفح:

| الحالة | ما يحدث |
|---|---|
| فعّال | كل شيء متاح ضمن حدود الخطة |
| منتهٍ (مضى تاريخ الانتهاء) | قراءة فقط: لا إضافة ولا تعديل ولا حذف، ويظهر تنبيه في أعلى كل صفحة |
| معلّق (من الأدمن) | لا يرى الأعضاء أي بيانات، وتظهر لهم رسالة التعليق. البيانات محفوظة وتعود عند التفعيل |

قبل الانتهاء بـ 7 أيام يظهر تنبيه للعيادة. حدود الخطة (عدد الطاقم مع المالك، وعدد المرضى) تُفحص عند الإضافة، ويمكن للأدمن وضع حد خاص لعيادة بعينها.

| الخطة | الطاقم | المرضى | شهرياً | سنوياً |
|---|---|---|---|---|
| تجريبية | 3 | 100 | — | — |
| أساسية | 2 | 300 | 5.99$ | 59$ |
| احترافية | 4 | 1000 | 13.99$ | 139$ |
| شاملة | بلا حد | بلا حد | 21.99$ | 219$ |

الخطط في جدول `plans`، وتُعدَّل من SQL Editor.

### لوحة الإدارة (`/admin`)
- قائمة العيادات مرتبة حسب أقرب انتهاء، مع تصفية (فعّالة، تنتهي قريباً، منتهية، معلّقة) وبحث بالاسم أو البريد أو الهاتف.
- **تسجيل دفعة:** يحفظ الدفعة ويمدد الاشتراك من تاريخ انتهائه، أو من اليوم إن كان منتهياً.
- **تعديل يدوي:** الخطة، الحالة، تاريخ الانتهاء، والحدود الخاصة.
- **حذف نهائي:** يتطلب كتابة اسم العيادة، ويحذف كل بياناتها.

كل هذه العمليات دوال في قاعدة البيانات تتحقق من أن المستدعي أدمن، والتطبيق لا يحمل مفتاح الخدمة.

## البنية

```
src/
  proxy.ts                 حماية الصفحات وتجديد الجلسة
  app/
    (auth)/                الدخول، التسجيل، إعداد العيادة أو الانضمام بدعوة
    (app)/                 الصفحات بعد الدخول
      page.tsx             لوحة التحكم
      appointments/        المواعيد وحالاتها
      patients/            المرضى وملف المريض
      visits/new/          تسجيل زيارة مع وصفة ودفعة
      prescriptions/[id]/  طباعة الوصفة
      payments/            المدفوعات
      settings/            إعدادات العيادة والطاقم والاشتراك
    admin/                 لوحة إدارة المنصة (العيادات والاشتراكات)
  components/              مكونات الواجهة المشتركة
  lib/
    session.ts             المستخدم والعيادة الحاليان
    subscription.ts        حالة الاشتراك (فعّال، منتهٍ، معلّق)
    time.ts                التواريخ بتوقيت العيادة
    labels.ts              النصوص والعملات والاختصاصات
    supabase/              اتصال Supabase وأنواع الجداول
supabase/
  migrations/              بنية قاعدة البيانات وسياساتها
  tests/                   اختبارات العزل والصلاحيات
```

## الطاقم
مالك العيادة يولّد رمز دعوة من **الإعدادات › طاقم العيادة**. ينشئ الطبيب أو السكرتير حساباً، ثم يختار "لدي رمز دعوة" ويدخل الرمز. الرمز صالح 7 أيام ولمرة واحدة.
